# Finance data-to-report and development handoff audit

Date: 19 November 2026. Read-only source audit; no accounting data, access or application behavior changed. No merge, commit, push, deployment or provider activation.

## Decision

The folder can be opened by another development agent, but it is **not a reconciled, current handoff or a user-acceptance-ready system**. Most Finance recording and report engines exist. Missing upstream integration, incomplete input coverage, several report semantics and actual staff acceptance prevent a blanket readiness claim.

Staff have declined the offline HTML reviewer (user, 19 November). Preserve its source evidence and prior work, but do not make staff use it or regard HTML answers as approved application setup. An in-system ownership/status/equivalence review remains the proposed replacement, not an implemented capability.

## Confirmed discrepancies reproduced on fictional data

1. **Pending liquidation appears in expense summary.** `routers/reports.py:174` selects `FundExpense.accepted IS NOT FALSE` without requiring finished checking/posted liquidation. `accepted` defaults NULL (`models.py:679`), so an unreviewed receipt appears as Spent while no expense journal exists. The same query remains in upstream `backend/modules/finance/routers/reports.py:174`. Reproduction: one pending receipt produces a summary amount while `checked_at` is NULL and there are no related entries. Choose and label submitted-spending vs approved-accounting semantics explicitly; do not silently change it in an audit.
2. **Unknown inventory cost becomes zero.** `routers/invoices.py:249-261` returns zero without setup/response and uses `(cost or 0)` for missing item costs; issuance adds cost legs only when a nonzero cost/defaults exist. Upstream retains this behavior. Fictional reproduction: missing item returns `[None], 0`. Margin reports expose an unknown-cost warning, but a balanced sale entry can still omit inventory cost. Resolve costing/hold policy before trusting profit and stock-value reconciliation.
3. **Tax and accounting sources differ.** Approved journal lines feed statements; purchase tax sources are recorded bills/posted petty cash/posted imported expenses. Marketing FundExpense and raw general journals do not automatically enter that purchase source union. This is a source-code coverage finding, not a tax-law conclusion.
4. **Historical forecast scope differs from cash date.** The upstream forecast starts from cash as of the selected day but selects invoices/bills using current status and cumulative paid totals. Use true as-of subledger logic if a reconstructed historical forecast is required, or clearly restrict/label its scope.

The first two findings are reproduced by two passing **observation** tests in the ignored isolated audit copy. A passing reproduction means the discrepancy exists; it does not mean it is fixed.
